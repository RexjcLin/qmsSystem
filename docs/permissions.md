# 角色與群組權限

## 權限來源

`Role.name` 是固定代碼，只允許 `ADMIN`、`QUALITY_MANAGER`、`INSPECTOR`，不可改名。中文名稱請編輯 `display_name`，說明請編輯 `description`。每位使用者只有一個角色，可以屬於多個 Django 群組。

角色會同步到同名的 Django 群組。儲存使用者或修改群組成員時，會移除不符合角色的專用群組，補上正確群組；其他自訂群組會保留。`is_staff` 也會依角色同步：管理員與品質主管可登入後台，檢驗員不可登入；超級使用者始終保留後台登入資格。

有效模型權限是「群組及個別權限的聯集」與「角色允許範圍」的交集。額外群組或個別授權不能突破角色上限。角色未知或未設定的普通帳號不具有 QMS 權限。超級使用者不受角色上限限制，但仍須啟用帳號。

## 權限矩陣

| 操作 | ADMIN 管理員 | QUALITY_MANAGER 品質主管 | INSPECTOR 現場品管員 |
|---|---|---|---|
| 登入管理後台 | 可以 | 可以 | 不可以 |
| 產品、檢驗項目及產品項目設定 | 查看、新增、修改、刪除 | 查看、新增、修改 | 查看，僅透過 API 等非後台途徑 |
| 檢驗批次、紀錄、結果 | 查看、新增、修改、刪除 | 查看、新增、修改 | 查看、開始／釋放自己的批次，新增檢驗紀錄及結果 |
| 不良類型、紀錄、圖片及改善措施 | 查看、新增、修改、刪除 | 查看、新增、修改 | 查看，無目前對應的專用 API |
| 普通使用者帳號 | 查看、新增、修改、刪除 | 不可以 | 不可以 |
| 角色中文名稱與說明 | 查看、修改 | 不可以 | 不可以 |
| 超級使用者帳號、群組設定、個別授權 | 僅超級使用者可管理 | 不可以 | 不可以 |
| 品質儀表板 | 可以 | 可以 | 可以 |

這是模型權限範圍，不代表每項功能都有 API。檢驗 API 對三種角色開放，並分別檢查 `view_inspectionbatch`、`view_productinspectionitem`、`add_inspectionrecord` 加 `add_inspectionresult`。批次開始及釋放檢查 `change_inspectionbatch`，普通檢驗員不能操作他人的批次；管理員及品質主管可釋放他人的批次，但不能直接代替負責人提交。每個 FAIL 自動建立缺陷，屬於檢驗提交交易的一部分，不開放檢驗員在後台任意新增或修改缺陷。

API 仍執行批次狀態、必填項目及量測規格等業務驗證。普通檢驗員的待檢清單限未指派或自己的批次。儀表板要求檢驗及不良紀錄查看權限，呈現全系統資料；目前沒有依部門限制資料範圍。

一般管理員不能修改或刪除超級使用者，也不能自行設定 `is_superuser`、`user_permissions`。後台的群組與 `is_staff` 欄位唯讀，由角色同步。只有超級使用者能管理 Django 群組與個別授權。一般管理員可以將普通帳號指派為 `ADMIN`，這是帳號管理權限的一部分。

## 套用及維護

```powershell
python manage.py migrate
python manage.py sync_role_permissions
```

同步指令建立三種角色與群組的標準權限，修正既有帳號的群組及後台資格，不變更密碼、`is_active`、`status` 或超級使用者身分。重新執行會恢復群組的標準權限，因此永久調整請修改 `accounts/rbac.py` 並更新測試；不要只在後台手動修改專用群組。

Migration 會將已知的中文角色「管理員」、「品質主管」、「現場品管員」合併到對應英文代碼，保留帳號與密碼；其他既有自訂角色不會被猜測映射，應自行確認後指派標準角色。合併無法在回滾時自動拆回原角色。

停用帳號可以取消 `is_active` 或設 `status=INACTIVE`，兩者都會阻止登入及 API 操作；再次啟用需兩者都處於啟用狀態。正常儲存帳號會同步角色；直接 SQL、`QuerySet.update()`、`bulk_create()` 或載入 fixture 不會執行使用者儲存訊號，完成這類操作後應執行同步指令。
